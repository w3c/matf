### Guidance in this document

This document describes how Web Content Accessibility Guidelines (WCAG) 2.2 principles, guidelines, and success criteria can be interpreted and applied to mobile applications, including native mobile apps, cross-platform mobile apps, hybrid mobile apps using web components, and mobile web apps. It provides informative (non-[normative](https://www.w3.org/TR/WCAG22/#dfn-normative)) guidance that does not set requirements.

#### Interpretation of web terminology in a mobile context

Where WCAG success criteria use web-specific terms or phrases such as “web page(s)”, this document provides equivalent terminology for mobile applications, such as “page(s)”. It also provides notes to explain the terminology replacements.

Some success criteria are written to apply to “a set of web pages” or “multiple web pages”. These criteria require the pages in the set to share some characteristic or behavior. Since the unit of conformance in WCAG 2 is a single web page, the Mobile Accessibility Task Force agreed that the equivalent unit of conformance for mobile applications is a single page within the application. It follows that an equivalent unit of evaluation for a “set of web pages” would be a “set of pages”, not — as previously interpreted in WCAG2ICT — as a “set of software”. These terms are defined in the [Key terms](#key-terms) section of this document. See “set of pages” to determine when a group of pages in a mobile application is considered a set.

The glossary terms were also reviewed and most of them applied to mobile applications, as written. Some applied with additional notes or edits (largely related to phrases like “web page(s)”), and a small number of terms were only used in Level AAA success criteria, which are not addressed by WCAG2Mobile at this time.
